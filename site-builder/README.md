# Bildy — בונה האתרים שלך (בסגנון Webild)

מערכת עצמאית לבניית אתרים עם AI: מתארים את העסק במשפט-שניים, Claude מייצר אתר שיווקי שלם
(קובץ HTML אחד, מעוצב ורספונסיבי), ואז עורכים אותו בצ'אט בשפה חופשית — "תחליף את הצבע לירוק",
"תוסיף מחירון", "תקצר את הטקסט בהירו". כל שינוי נשמר כגרסה עם אפשרות שחזור, ובסוף מייצאים ZIP
שאפשר להעלות לכל אחסון.

**אינטגרציית GoHighLevel מובנית:** כל טופס "צור קשר" באתרים שנוצרים שולח את הליד לשרת שלך,
שמעביר אותו אוטומטית כ-Contact ל-Location (סאב־אקאונט) של הלקוח ב-GHL — התשתית למכירת
המערכת כ-SaaS לעסקים בארץ.

## התקנה והפעלה

```bash
cd site-builder
npm install
cp .env.example .env    # ולמלא מפתחות
npm start               # http://localhost:4000
```

בלי `ANTHROPIC_API_KEY` המערכת עולה ב**מצב דמו** — כל הזרימה עובדת (יצירה, גרסאות, לידים,
ייצוא) אבל האתר שנוצר הוא תבנית לדוגמה. עם המפתח, היצירה והעריכה רצות על Claude
(ברירת מחדל: `claude-opus-4-8`).

> עלויות: כל יצירת אתר היא קריאת API בתשלום (בדרך כלל סנטים בודדים עד ~$1 לאתר, תלוי בגודל).
> אין "ללא הגבלה" אמיתי — המגבלה היא קרדיט ה-API שלך.

## איך זה בנוי

```
site-builder/
├── server.js          # Express: פרויקטים, יצירה/עריכה ב-SSE, לידים, preview, ייצוא ZIP
├── lib/
│   ├── anthropic.js   # קריאות ל-Claude (streaming, adaptive thinking)
│   ├── prompts.js     # פרומפטים ליצירת אתר ולעריכה (רמת סוכנות, בלי "AI slop")
│   ├── ghl.js         # שליחת לידים ל-GoHighLevel (LeadConnector API v2)
│   ├── store.js       # אחסון פרויקטים/גרסאות/לידים בקבצים (data/)
│   └── demo.js        # מצב דמו ללא מפתח API
├── public/            # הממשק: דשבורד + עורך (צ'אט + preview + גרסאות + לידים)
└── data/              # נוצר אוטומטית, לא נכנס לגיט
```

- **גרסאות:** כל יצירה/עריכה נשמרת כ-`v1, v2, ...` עם מצביע `head`. אפשר לצפות בכל גרסה
  ולשחזר אליה.
- **לידים:** האתרים שנוצרים מקבלים `LEAD_ENDPOINT` שמצביע ל-`/api/lead/<project>`. הליד נשמר
  מקומית **וגם** נשלח ל-GHL אם מוגדר. יש טאב "לידים" בעורך עם סטטוס סנכרון לכל ליד.

## חיבור GoHighLevel

1. ב-GHL (ברמת ה-Agency או ה-Location): **Settings → Private Integrations → Create** עם scope
   של `contacts.write`. את הטוקן שמים ב-`.env` כ-`GHL_API_KEY`.
2. את ה-**Location ID** של סאב־האקאונט שמקבל את הלידים שמים ב-`GHL_LOCATION_ID`
   (ברירת מחדל), או פר-פרויקט דרך ⚙ הגדרות בעורך — ככה כל אתר-לקוח מזין את הסאב־אקאונט שלו.
3. אפשר להוסיף תגיות פר-פרויקט (למשל `bildy, website-lead`) לאוטומציות ב-GHL.

אתר שיוצא ב-ZIP ומתארח בדומיין אחר צריך שה-`LEAD_ENDPOINT` בקובץ יצביע לכתובת המלאה של
שרת ה-Bildy שלך (מוסבר גם ב-README.txt שבתוך ה-ZIP).

## מפת דרכים ל-SaaS

מה שיש כאן הוא הליבה המוצרית (v1). כדי למכור את זה כ-SaaS צריך להוסיף:

1. **משתמשים והרשאות** — הרשמה/כניסה (למשל Clerk/Auth.js), פרויקטים פר-משתמש.
2. **חיוב** — מנויים (Stripe / Grow-משולם בארץ), מכסת אתרים לפי חבילה.
3. **אחסון ודומיינים** — פרסום בלחיצה (Cloudflare Pages/Netlify API) וחיבור דומיין ללקוח.
4. **DB אמיתי** — להחליף את אחסון הקבצים ב-Postgres/SQLite כשיש יותר ממשתמש אחד.
5. **GHL SaaS Mode** — אם עובדים עם GHL Agency Pro, אפשר לפתוח סאב־אקאונט אוטומטית לכל
   לקוח חדש דרך ה-API ולשדך אותו לפרויקט (השדה כבר קיים בהגדרות הפרויקט).
6. **אבטחה** — rate limiting, CAPTCHA על טפסי לידים, ולידציה קשוחה יותר.

## API פנימי (תמצית)

| Method | Path | מה עושה |
|---|---|---|
| GET | `/api/health` | מצב (דמו/מודל/GHL) |
| GET/POST | `/api/projects` | רשימה / יצירת פרויקט |
| GET/PATCH/DELETE | `/api/projects/:id` | פרטים / עדכון (שם, GHL) / מחיקה |
| POST | `/api/projects/:id/generate` | יצירת האתר (SSE) |
| POST | `/api/projects/:id/edit` | עריכה בצ'אט (SSE) |
| POST | `/api/projects/:id/revert` | שחזור לגרסה |
| GET | `/api/projects/:id/leads` | לידים שנקלטו |
| POST | `/api/lead/:id` | קליטת ליד מהאתר (CORS פתוח) + סנכרון GHL |
| GET | `/preview/:id`, `/preview/:id/v/:v` | תצוגת האתר |
| GET | `/api/projects/:id/export` | הורדת ZIP |
