# Workflow: Competitor Analysis & Market Monitoring

## Objective
Discover the business's competitors, research how they price, what they ship, and
how they position themselves, then produce a **branded PDF** report that highlights
what competitors do well and where this business can win. Re-runnable: each run is
saved as a dated snapshot so the market can be tracked over time.

## Inputs
- `business/profile.md` — who we are, our offering, ICP, differentiators, seed
  competitors and buyer search terms. The agent reads this to drive discovery.
- `brand/logo.png` — the company logo (user-provided). Required for branding.
- `brand/brand.yaml` — company name, palette, fonts. Generated by `extract_palette.py`,
  then hand-tuned (company_name, tagline, fonts).
- Optional `FIRECRAWL_API_KEY` in `.env` — enables rendering of JS-heavy sites.

## Tools used
- `tools/extract_palette.py --logo brand/logo.png` — derive brand colors from the
  logo and write/merge `brand/brand.yaml`.
- `tools/scrape_site.py --url <url>` — fetch a competitor page into a JSON snapshot
  under `data/snapshots/<date>/`. Returns title, description, headings, pricing
  signals, and cleaned text.
- `tools/render_report_pdf.py --content <report.md> [--title ... --logo ... --brand ...]`
  — render the finished report markdown into `reports/competitor_analysis_<date>.pdf`.

## Steps

### First run only — setup
1. Confirm `brand/logo.png` exists. If not, ask the user to drop it in `brand/`.
2. Run `tools/extract_palette.py --logo brand/logo.png`. Show the user the detected
   primary/secondary/accent hexes; let them override in `brand/brand.yaml`.
3. Propose 2–3 font pairings (heading/body). On the user's pick, set `fonts:` in
   `brand/brand.yaml`. To use exact brand typefaces, drop `.ttf/.otf` files whose
   filename contains the font name into `brand/fonts/` (the renderer auto-detects them);
   otherwise clean system fallbacks are used.
4. Fill in `business/profile.md` (interview the user or have them paste info). This is
   the fuel for competitor discovery — don't skip it.

### Every run
5. Read `business/profile.md`. Build a discovery query set from our offering + buyer
   search terms. Use web research to assemble a competitor list (seed list from the
   profile + newly discovered names). Aim for ~5–10 of the most relevant.
6. For each competitor, run `tools/scrape_site.py` on their **homepage, pricing page,
   and a features/product page** when available. Snapshots land in
   `data/snapshots/<date>/`.
7. Synthesize a report markdown file at `data/snapshots/<date>/report.md` with these
   sections:
   - **Executive summary** (3–5 bullets, the "so what")
   - **Market overview** (landscape, segments, pricing norms)
   - **Per-competitor profiles** — pricing & packaging · features & capabilities ·
     positioning & messaging · what's working for them
   - **Comparison matrix** (markdown table: competitors × dimensions, include us)
   - **Our gaps & opportunities** — where they beat us, where the open lanes are
   - **Recommended actions** (prioritized, concrete)
   - **What changed since last snapshot** (see step 9)
8. Render the PDF:
   `python tools/render_report_pdf.py --content data/snapshots/<date>/report.md --title "Competitor Analysis"`
   Verify `reports/competitor_analysis_<date>.pdf` opens with the logo on the cover +
   page headers, brand colors, and page numbers.

### Change tracking
9. If a previous folder exists under `data/snapshots/`, compare the prior `report.md`
   / snapshots against this run and write the differences (new entrants, pricing
   changes, new features, positioning shifts) into the "What changed" section.

## Expected output
- `reports/competitor_analysis_<YYYY-MM-DD>.pdf` — the branded deliverable.
- `data/snapshots/<YYYY-MM-DD>/` — raw page snapshots + `report.md` (history for diffing).

## Edge cases & lessons learned
- **PDF engine auto-detects.** `render_report_pdf.py` tries WeasyPrint first and
  falls back to headless Chromium (Playwright). Force one with `--engine weasyprint`
  or `--engine chromium`.
  - **This machine has no Homebrew, so Chromium is the active engine** (verified
    working: branded cover + logo header + page-number footer). Chromium is already
    installed via `playwright install chromium`.
  - To switch to WeasyPrint later (nicer paged-media control), install native libs:
    `brew install pango` (pulls cairo, gdk-pixbuf, libffi). No code change needed —
    auto-detect will prefer it.
  - Chromium renders the cover and body as two PDFs (full-bleed cover + body with
    header/footer) and merges them with pypdf; that's why the cover has no page chrome.
- **Logo on colored cover:** the cover sits on a brand-gradient; the CSS puts the logo
  on a white plate so dark or transparent logos stay legible. Swap to a white/SVG
  logo variant if available for a cleaner look.
- **Black/white-only logos:** `extract_palette.py` skips near-white/near-black/grey, so
  a monochrome logo yields no hues — set `palette` manually in `brand.yaml`.
- **JS-heavy / blocked pages:** plain requests may get a thin or 403 page. Set
  `FIRECRAWL_API_KEY` to render those, or have the agent use its own web research and
  paste findings into the report rather than relying on the scrape.
- **Pricing behind a "contact sales" wall:** record "custom / sales-led" rather than
  guessing a number.
- **Snapshots are persistent** (not `.tmp/`) — they're the history that powers change
  tracking. Don't delete old snapshot folders.
