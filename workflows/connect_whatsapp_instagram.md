# Workflow: חיבור הסוכן לוואטסאפ ולאינסטגרם (ישירות, בלי ManyChat)

## Objective
לחבר את סוכן ה-AI של ZYNX לוואטסאפ ולאינסטגרם DM של קליניקה, כך שהוא עונה אוטומטית —
**ישירות מול ה-API של מטא**, בלי תלות בפלטפורמת צד-ג' כמו ManyChat.

## איך זה עובד (הארכיטקטורה)
```
לקוחה כותבת בוואטסאפ/אינסטגרם
        │
        ▼
   מטא שולחת Webhook  ──►  השרת שלך (tools/clinic_bot_whatsapp.py / demo_server.py)
                                   │  בונה System Prompt עם נתוני הקליניקה
                                   ▼
                              Claude API  (מבין, עונה, מסנן)
                                   │   + יומן + CRM
                                   ▼
                         השרת שולח תשובה חזרה דרך ה-API של מטא
```
**הנקודה:** השרת הזה = מה ש-ManyChat עושה. אתה הבעלים שלו → יותר שליטה, מרווח גבוה יותר,
ואתה ספק אמיתי ולא משווק של כלי של מישהו אחר.

---

## חלק 1 — וואטסאפ

### מסלול A — רשמי (מומלץ ללקוחות משלמים): WhatsApp Cloud API
1. פתח **Meta Business Account** + **Meta for Developers App**.
2. הוסף את מוצר **WhatsApp** → קבל מספר טסט / חבר מספר עסקי אמיתי.
3. הגדר **Webhook** שמצביע על השרת שלך (`/webhook`), עם Verify Token.
4. הרשאות: `whatsapp_business_messaging`. עובר **App Review** של מטא (אישור חד-פעמי).
5. השרת מקבל הודעות נכנסות ושולח תשובות דרך ה-Graph API.
- **עלות:** יש שכבה חינמית, ואז תמחור לפי שיחה/הודעה (זול). לאמת מול דף התמחור של מטא.

### מסלול B — ספק (הכי מהיר להתחיל): GreenAPI / 360dialog / Twilio
- **GreenAPI** — לא-רשמי, מהיר וזול, מתאים לדמו ולהתחלה (סיכון חסימה — לא לנפח).
- **360dialog / Twilio** — BSP רשמיים, יציבים ללקוחות משלמים.
- הקוד שלנו `tools/clinic_bot_whatsapp.py` כבר מוכן ל-**GreenAPI** (Webhook → Claude → שליחה).
  למעבר ל-Cloud API משנים רק את פונקציית `send_whatsapp()` — הלוגיקה זהה.

## חלק 2 — אינסטגרם DM

> אינסטגרם הוא חלק מ-Graph API של מטא — אותו עולם בדיוק כמו וואטסאפ.

1. חשבון האינסטגרם של הקליניקה חייב להיות **Professional (Business)** ו**מקושר ל-Facebook Page**.
2. באותו **Meta App** → הוסף מוצר **Instagram** + הרשאות **`instagram_manage_messages`**.
3. הגדר **Webhook** לאירועי `messages` (DM נכנס) → מצביע על השרת שלך.
4. השרת מקבל את ה-DM, מריץ Claude, ושולח תשובה דרך ה-Graph API (`/me/messages`).
5. עובר **App Review** של מטא (הרשאת מסרים דורשת אישור — מציגים וידאו של הזרימה).

> זה אותו שרת ואותו מוח (Claude) — רק "צינור" כניסה/יציאה אחר. בונים handler לאינסטגרם
> במקביל ל-WhatsApp (אפשר לאחד לשרת אחד שמטפל בשני הערוצים).

## ManyChat מול חיבור ישיר (מתי מה)
| | ManyChat | חיבור ישיר (שלך) |
|---|---|---|
| מהירות הקמה | מיידי, no-code | דורש Meta App + App Review |
| שליטה / מיתוג | מוגבל | מלא — זה המוצר שלך |
| עלות | מנוי חודשי לכל לקוח | עלות שרת זניחה + API |
| מרווח רווח | נמוך יותר | גבוה — אתה הפלטפורמה |
| מתאים ל | בדיקה מהירה / לקוח ראשון | סקייל ורצינות |

**המלצה:** התחל אפילו עם GreenAPI/ManyChat ללקוח הראשון כדי לסגור מהר, ובמקביל הקם את
החיבור הישיר (השרת שלנו) — וזה הופך אותך לספק אמיתי עם מרווח גבוה.

## Edge cases & lessons learned
- App Review של מטא לוקח ימים — התחל אותו מוקדם.
- אל תשתמש ב-API לא-רשמי (GreenAPI) לנפחים גדולים — סיכון חסימה.
- שמור Verify Token ו-Access Tokens ב-`.env`, לעולם לא בקוד.
